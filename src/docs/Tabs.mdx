# Tabs / ManagedTabs

This page documents **`Tabs`** as the presentational list of **`Tab`** elements and **`ManagedTabs`** as the selection context + visual tablist. For panels, full composition, imports, and keyboard/a11y contracts, start at [Tabs overview](?path=/docs/docs-tabs-overview--docs).

`ManagedTabs` / `Tabs` are for the **tab list** only. For panels, compose `ActiveTabContextProvider` + `Tabs` + `TabPanel` yourself.

Import the presentational list as `Tabs` when you already have (or need) `ActiveTabContextProvider`; use `ManagedTabs` only when you want a self-contained selectable list with no sibling panels under that provider. Do not nest `ManagedTabs` under an existing active-tab provider — [ManagedTabs nesting](?path=/docs/docs-tabs-overview--docs#managedtabs-nesting).

A common use case is when selection comes from outer context or the URL — resolve the value, pass it as `activeTab`, and write back on change:

```tsx
const tab = searchParams.get("tab") ?? "overview";

<ManagedTabs
  activeTab={tab}
  onActiveTabChange={(next) => {
    setSearchParams({ tab: next });
  }}
>
  <Tab value="overview">Overview</Tab>
  <Tab value="billing">Billing</Tab>
</ManagedTabs>
```

## Overflow

`Tabs` does not apply `overflow-x` itself — a scrollport would clip tab `:focus-visible` outlines, so the host owns overflow (and any padding that keeps focus chrome visible) via `className`. This story uses that pattern plus `autoScrollBehavior="smooth"` so the selected tab scrolls into view. Default `autoScrollBehavior` is `"none"` (opt-in). Rationale and host CSS: [Tabs overview — Overflow](?path=/docs/docs-tabs-overview--docs#overflow).

## Root element

`Tabs` is internally a `<div role="tablist">`, so you can pass native div props (`id`, `className`, `aria-label`, `aria-labelledby`, …) and they land on that root.

`data-variant`, `data-size`, and `data-activation` are set from the `variant` / `size` / `activation` props — values you pass for those attributes are overwritten. `orientation` maps to `aria-orientation`; `autoScrollBehavior` is not a DOM attribute. Keyboard modes: [Tabs overview — Keyboard](?path=/docs/docs-tabs-overview--docs#keyboard).

`ManagedTabs` adds no extra DOM node: selection props go to the provider; everything else forwards to `Tabs`.
