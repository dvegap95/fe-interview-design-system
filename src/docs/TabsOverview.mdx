# Tabs overview

Public entry point for the Tabs system: composition, imports, accessibility, and escape hatches. Per-component docs (playgrounds + API) live under **Docs**; interactive CSF stories also appear under **Components**.

## Install and import

Peer deps: `react` and `react-dom` ^19. Import components and helpers from the package root, context helpers from subpaths, and styles once:

```tsx
import {
  Badge,
  CssBaseline,
  ManagedTabs,
  Tab,
  TabPanel,
  Tabs,
  cn,
} from "fe-interview-design-system";
import { ActiveTabContextProvider } from "fe-interview-design-system/context/activeTabContext";
import "fe-interview-design-system/style.css";
// Host theme after package CSS when overriding :root tokens (see Theming):
// import "./acme-theme.css";

// Optional: mounts Inter + global baseline. Also emits default CSS tokens on :root.
// <CssBaseline />

// Class merge helper (same idea as clsx):
// cn(styles.root, condition && styles.active, className)
```

Also available: `fe-interview-design-system/context/sizeContext`, `.../tabVariantContext`. See [Public helpers and contexts](#public-helpers-and-contexts) for when to use each.

`style.css` is the built package stylesheet (component CSS + token defaults). If you also ship a host theme that redefines the same `:root` variables, **import the host theme after** `style.css` so it wins the cascade. Prefer a wrapper class (below) when you want to avoid load-order races.

## Mental model

- **`Tabs`** — visual tablist (`role="tablist"`) only. Pushes `variant` / `size` via context. Does **not** own selection.
- **`ManagedTabs`** — `ActiveTabContextProvider` + `Tabs` for a selectable **tab list** when you do not need sibling panels under the same provider.
- **`Tab`** — one tab. Selection from active-tab context; optional `selected` for standalone chrome. Under the provider, `value` is required for clicks to change selection.
- **`TabPanel`** — content for a `value`. Requires `ActiveTabContextProvider` (compose explicitly with `Tabs`, not `ManagedTabs`).
- **`Badge`** — optional trailing UI via `Tab` `slots.end`.

**Panels are siblings of the tablist under the provider** — not children of `ManagedTabs` / `Tabs`. For tabs + panels, use `ActiveTabContextProvider` + `Tabs` + `TabPanel` as below.

> **Warning:** Do **not** nest `ManagedTabs` inside an existing `ActiveTabContextProvider` (or expect outer selection/`value` state to flow into it). `ManagedTabs` mounts its **own** provider, so it will not inherit the surrounding active-tab context. Use presentational `Tabs` when you already own the provider.

## Recommended composition

```tsx
<ActiveTabContextProvider defaultActiveTab="a">
  <Tabs aria-label="Sections">
    <Tab
      id="tab-a"
      value="a"
      aria-controls="panel-a"
    >
      A
    </Tab>
    <Tab
      id="tab-b"
      value="b"
      aria-controls="panel-b"
    >
      B
    </Tab>
  </Tabs>
  <TabPanel
    id="panel-a"
    value="a"
    aria-labelledby="tab-a"
  >
    …
  </TabPanel>
  <TabPanel
    id="panel-b"
    value="b"
    aria-labelledby="tab-b"
  >
    …
  </TabPanel>
</ActiveTabContextProvider>
```

## Public helpers and contexts

| Export | From | When to use |
| --- | --- | --- |
| `cn` | package root | Merge class names on host wrappers or when forwarding `className` into roots (same idea as `clsx`). |
| `CssBaseline` | package root | Optional once-per-app mount for Inter + global baseline + default `:root` tokens. Skip if the host DS already owns fonts/baseline and only needs `style.css` + token overrides. |
| `ActiveTabContextProvider` / `useActiveTabContext` | `…/context/activeTabContext` | Own selection when composing `Tabs` + sibling `TabPanel`s (or any custom chrome that must share the same active value). Prefer this over `ManagedTabs` whenever panels (or other siblings) need the same provider. |
| `ManagedTabs` | package root | Convenience only: provider + `Tabs` for a **list-only** selectable tab strip. Do not nest it inside another active-tab provider. |
| `SizeProvider` / `useResolvedSize` | `…/context/sizeContext` | Advanced: push or read `sm` \| `md` outside a `Tabs` tree (e.g. host layout that sizes nested `Badge`s the same way). Everyday size comes from `Tabs` / `Tab` props. |
| `TabVariantProvider` / `useResolvedTabVariant` | `…/context/tabVariantContext` | Advanced: push or read `pill` \| `underline` outside a `Tabs` tree. Everyday variant comes from `Tabs` / `Tab` props. |

Resolution for visual tokens is always **`prop ?? nearest context ?? default`**. Selection is separate: only `ActiveTabContextProvider` (or `ManagedTabs`) owns active value.

## DOM wrappers (context, not hierarchy)

`Tabs` / `Tab` / `TabPanel` coordinate through React context and role queries — they do **not** require a fixed child tree under the tablist. Host layout wrappers are fine:

```tsx
<Tabs aria-label="Sections">
  <div className="host-cluster">
    <Tab value="a">A</Tab>
    <span className="host-wrap">
      <Tab value="b">B</Tab>
    </span>
  </div>
</Tabs>
```

Variant / size still flow from `Tabs` → descendants, selection still flows from `ActiveTabContextProvider`, and keyboard navigation finds `[role="tab"]` inside the tablist (including nested ones). Use wrappers for host layout; keep WAI-ARIA `id` / `aria-controls` / `aria-labelledby` wiring on the tab and panel elements themselves.

## Selection

- **Uncontrolled:** `defaultActiveTab` on the provider / `ManagedTabs`.
- **Controlled:** `activeTab` + `onActiveTabChange`. If the parent does not update `activeTab`, the UI will not move (callback still fires).

Demos: [Tabs — Controlled](?path=/docs/docs-tabs--docs#controlled).

## Prop vs context

Visual props resolve as **`prop ?? context ?? default`**. A Tab can override list-level `variant` / `size` — demo on [Tab — Prop overrides context](?path=/docs/docs-tab--docs#prop-overrides-context).

Do **not** pass `selected` on `Tab` while it also sits under `ActiveTabContextProvider` with an active value — that mix logs a console warning. Details: [Tab — selected vs context](?path=/docs/docs-tab--docs#selected-vs-context-console-warning).

## Badge on a tab

## Keyboard

Built into the tablist:

- Roving `tabIndex` — with a provider and a non-empty `activeTab`, only the selected tab is in the tab order (`0`; others `-1`). Outside the provider, or while `activeTab` is still empty, every tab stays `tabIndex={0}` (no single selection to rove yet).
- Arrow keys move focus (horizontal vs vertical follows `orientation`)
- `Home` / `End` jump to first / last enabled tab
- `Enter` / `Space` activate the focused tab
- `disabled` tabs are skipped — demo on [Tabs — Disabled](?path=/docs/docs-tabs--docs#disabled-tabs)

## Accessibility

When composing panels, wire the WAI-ARIA tabs pattern:

- Tablist name: `aria-label` or `aria-labelledby` on `Tabs`
- Tab: `id` + `aria-controls={panelId}`
- Panel: `id` + `aria-labelledby={tabId}`

`aria-selected`, `role`, and `aria-orientation` are handled by the components.

`ManagedTabs` playgrounds name the tablist with `aria-label` (list-only demos). Full tab↔panel linkage belongs on the explicit provider + `Tabs` composition (Composition / CustomStyled) — that split is intentional, not a missing feature.

## Overflow

For narrow viewports, set `autoScrollBehavior` to a `ScrollBehavior` (`auto` / `smooth` / `instant`) so the selected tab scrolls into view within the tablist. `"none"` (default) disables auto-scroll entirely — see [Tabs — Overflow](?path=/docs/docs-tabs--docs#overflow). Scrolling uses `block: "nearest"` so the page does not jump vertically when only the tablist needs to move.

## Theming (CSS tokens)

Components read shared values through CSS custom properties (colors, spacing, typography). Defaults live on `:root` and ship with `style.css` / `CssBaseline`. A larger design system can override them without forking component SCSS.

**Scoped theme** (recommended — no fight over global `:root` order):

```css
.acme-theme {
  --color-surface-inverse: #0b3d2a;
  --color-surface-inverse-hover: #145c40;
  --color-surface-inverse-active: #1e7a56;
  --font-size-body-sm: 10px;
  --line-height-body-sm: 150%;
}
```

```tsx
<div className="acme-theme">
  <Tabs aria-label="Sections">…</Tabs>
</div>
```

**Global `:root` override** (must load after `fe-interview-design-system/style.css`):

```css
:root {
  --color-surface-inverse: #0b3d2a;
  --font-size-body-sm: 10px;
}
```

Typography mixins (`body-medium` / `body-small`) use:

| Token | Default | Used by |
| --- | --- | --- |
| `--font-family` | Inter stack | both |
| `--font-size-body-md` | `14px` | Tab, TabPanel |
| `--line-height-body-md` | `150%` | Tab, TabPanel |
| `--font-size-body-sm` | `12px` | Badge |
| `--line-height-body-sm` | `150%` | Badge |

Color / spacing tokens follow the same pattern (e.g. `--color-surface-inverse`, `--spacing-xs`). Use tokens when you want brand-wide value swaps; use `className` (below) when you need structural restyles tokens cannot express.

## Custom styling

Every root accepts `className` (merged with internal styles via `cn`). This demo intentionally breaks the default look on the tablist, tabs, badge, and panels.

Prop-driven visual state is exposed as **stable data attributes** on those roots (not hashed CSS-module class names):

| Attribute | On | Values |
| --- | --- | --- |
| `data-variant` | `Tabs`, `Tab`, `Badge` | Tab/Tabs: `pill` \| `underline`; Badge: `neutral` \| `positive` \| `negative` |
| `data-size` | `Tabs`, `Tab`, `Badge` | `sm` \| `md` |
| `aria-selected` | `Tab` | `"true"` \| `"false"` (selection; prefer this over inventing a parallel hook) |

Use `className` for structural restyles, and attribute selectors when you need to branch on variant/size/selection.

### Escape-hatch demo

Pass your own classes into each root, then key off the public hooks:

```scss
.myTabs {
  gap: 12px;

  &[data-variant="pill"] {
    gap: 16px;
  }
}

.myTab {
  text-transform: uppercase;

  &[data-variant="underline"] {
    letter-spacing: 0.12em;
  }

  &[data-size="sm"] {
    padding: 6px 10px;
  }

  &[aria-selected="true"] {
    box-shadow: 4px 4px 0 currentColor;
  }
}

.myBadge[data-variant="negative"] {
  border-color: #5a1010;
}
```
